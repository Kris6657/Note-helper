# Note-helper

把**外语课件原文**和**AI 按课件顺序生成的中文笔记**并排放在一个窗口里对照复习。点笔记里的页码标签，左边课件就跳到那一页。

```
┌──────────────────────────┬──────────────────────────┐
│  课件 PDF（只读）         │  notes.md（只读）         │
│                          │                          │
│  第 7 页 ────────────────┼──▶（P7） 正义即公平       │
│                          │    · 分配正义…           │
│  滚动                    │    （P8） 平等自由原则    │
└──────────────────────────┴──────────────────────────┘
                                   ▲
                        批注写进 annotations.json（唯一写入点）
```

## 第一次运行

已提供本地 Windows x64 便携预览的构建方式，使用与升级见 [便携版说明](便携版说明.md)；当前尚未公开 Release。以下是**源码运行方式**：阅读服务需要 Python 3.8+，服务端只用标准库，前端没有 npm 安装或构建步骤。首次准备前端资源可能需要联网，准备好后可离线使用。

在解压后的项目根目录打开 PowerShell，按下面的顺序操作。

### 1. 确认 Python 能运行

```powershell
python --version
```

若系统使用 `py` 启动器，下面命令中的 `python` 可换成 `py -3`。若找不到解释器，请先安装 [Python](https://www.python.org/downloads/)；Windows 安装时勾选加入 PATH。

### 2. 准备前端资源

源码中的 `web/vendor/` 不入 Git。新下载的源码需要先准备资源；复制已有完整文件夹的人可先检查：

```powershell
python tools/prepare_vendor.py --check
```

如果缺少资源，可明确允许脚本从 npm 官方仓库下载固定版本包：

```powershell
python tools/prepare_vendor.py --download
```

这只准备本项目的前端文件，不安装 npm，也不修改系统配置。已有文件的校验值不符时会停止，不会自动覆盖。已有两个固定版本的 `.tgz` 包时，也可以离线准备：

```powershell
python tools/prepare_vendor.py --archive "pdfjs-dist=包目录/pdfjs-dist-3.11.174.tgz" --archive "marked=包目录/marked-12.0.2.tgz"
```

把示例中的「包目录」换成实际目录。版本、官方来源与 SHA-256 见 [vendor-manifest.json](vendor-manifest.json)。运行服务本身不会下载资源。

### 3. 放入自制演示课程

将 `examples/演示课程/` 整个文件夹复制到 `courses/` 下。没有 `courses/` 时先新建；如果已经有 `courses/演示课程/`，直接使用它，不要重复合并或覆盖。

首次复制也可以执行：

```powershell
if (Test-Path -LiteralPath ".\courses\演示课程") {
    throw "演示课程已存在，请直接启动，不要重复复制。"
}
New-Item -ItemType Directory -Path ".\courses" -Force | Out-Null
Copy-Item -LiteralPath ".\examples\演示课程" -Destination ".\courses\演示课程" -Recurse
```

示例包含 [三页英文课件](examples/演示课程/Module%201/slides.pdf) 与 [对应中文笔记](examples/演示课程/Module%201/notes.md)，图表和数字全部自制、虚构，沿用仓库的 MIT 许可证。应用不会向 `examples/` 写批注。

### 4. 检查并启动

```powershell
.\start.bat --check
.\start.bat
```

浏览器会自动打开，地址以终端显示为准。终端窗口是服务本体；操作后等到「已保存」再退出，关闭终端会停止服务。不要双击 `web/index.html` 或把前端文件单独放进其他静态服务器。

### 5. 用示例走一遍

1. 左上选择「演示课程 · Module 1」，左栏应显示三页英文课件，右栏是中文笔记。
2. 点笔记里的 `P2` 标签，确认左栏跳到第二页。
3. 点「星标」，将页面筛选切为「星标页」，应只剩第二页；再切回「全部页面」。
4. 切到「批注」，点笔记块，设置颜色、填写评论或勾选「已掌握」。
5. 按 `Ctrl+S`，看到「已保存」后刷新；确认刚才的标记与评论仍在。

遇到错误先看下方「出问题了」。示例的操作结果保存在 `courses/演示课程/Module 1/annotations.json`，不会写进示例原件或 Git。

规则只有三条：

1. 一门课一个文件夹，放在 `courses/` 下
2. 每个模块一个文件夹，**必须叫 `Module N`**（`Module 3`、`Module_3`、`Module3` 都认）
3. 模块文件夹里固定叫 `notes.md` 和 `slides.pdf`

满足这三条，工具启动时自动全部发现，不需要任何配置文件。

### 加一门新课

1. 建 `courses/新课名/Module 1/`
2. 课件 PDF 复制进去改名 `slides.pdf`
3. 按 `tools/笔记生成提示词.md` 生成 `notes.md`

本工具只负责对照阅读与批注，**不会自动生成中文笔记或转换 PPTX**。使用外部 AI 生成笔记时，课件是否允许发送给该服务，需要由你另行确认。

笔记中的页码支持 `（P7）`、`（P7–P15）`、`（P11、P14）`。PDF 使用原始页码；页码写错时请在应用外修改笔记。

## 掌握点怎么算

**按 Markdown 的标题层级切，不按块切。** 一份笔记里 200 多个块，大部分是 bullet 和表格行，拿它们当"掌握点"没有意义。

切分规则：

- **存储永远落在「叶子标题」上**——下面没有更深标题的标题。所以切换粒度**不会丢勾选**。
- **展示粒度可切**，下拉里直接标出各层级的个数，一眼看出粗细：
  - `最细（22）` —— 每个叶子标题一个知识点
  - `2 级标题（6）` —— 一个 H2 算一个，要它底下**全部**细条目都打钩才算已掌握
  - `3 级标题（19）`
- **一级标题默认不出现**。它通常是分节符（`# 第一部分：...`），底下必然有下级，列出来只会让人困惑。只有整份笔记只有 H1 时才会出现。
- 切换粒度后如果某节只勾了一部分，计数会显示 `已掌握 0 / 6（1 节进行中）`，不会让你以为勾选丢了。

**块**是可标注的最小单位：段落 / 列表项 / 标题 / 代码块 / **表格的每一行**。表格按行切而不是整表切——一张对照表里每一行往往就是一个独立考点，整表共用一个颜色太粗。

## 笔记格式约定

页码写成三种形式之一，全角括号：

```
（P7）            单页
（P7–P15）        连续范围（注意中间是 – 不是减号）
（P11、P14）      不连续多页
```

页码是**块级 + 继承**：标题带页码，它下面的列表项如果自己没标，就继承最近一次出现的页码。所以不用每行都堆页码。

跨模块引用写成 `[[Module 2]]`，不要写成「参见 Module 2」。

**页码存的是人可读的 `（P7）`，不是链接。** 工具的职责只是把它渲染成可点的标签 —— 所以 `notes.md` 拿到任何地方裸读都不违和，也不会被这个工具绑架。

## 数据边界

| 文件 | 工具会写它吗 |
|---|---|
| `notes.md` | **不会**，全程只读 |
| `slides.pdf` | **不会**，全程只读 |
| `annotations.json` | 会，唯一位于模块目录内的写入点 |

批注和笔记正文是两回事，分开存：笔记保持 AI 原样，批注单独一份 JSON（人可读、可 diff、可带走）。将来想统计「哪几页我标得最多」这种复习线索，数据是现成的。

**批注会不会因为笔记重新生成而错位？** 会——批注是按「块在文档里的序号」绑定的，笔记中间插进一行，后面的块就集体后移一位，批注会跟着挂到别的段落上：不报错、不丢数据，只是错了，属最难发现的那类问题。所以每条批注都带一份**内容指纹**（块文字的哈希）。打开模块时逐条核对：

- 指纹能唯一对上号的，自动搬回正确的位置；
- 对不上、或全文里有多处同文的（分不清是哪个），**不猜**——从活跃批注里摘出来存进 `meta.orphans`，界面上告个数。既不静默删除，也不允许它挂在错误的块上。

自动归位会更新批注文件。修改或重生成笔记前，先关闭服务并备份整个课程目录。

**保存失败时不要直接刷新。** 当前修改仍在页面内存里。普通写入失败可检查磁盘空间和权限，再按 `Ctrl+S` 重试；若提示其他窗口已修改，请先把当前评论复制到安全位置，再重新载入和核对。不要把空文件覆盖到损坏的批注上。

`courses/` 不受本项目 Git 保护。备份时同时保留 `notes.md`、`slides.pdf` 和 `annotations.json`；浏览器里的主题、模式与上次模块不属于课程备份。

## 第三方组件

阅读服务使用 Python 标准库；前端资源放在 `web/vendor/`，通过准备脚本获取并在本机加载：

| 组件 | 版本 | 许可证 | 用途 |
|---|---|---|---|
| pdf.js（Mozilla） | **3.11.174**（build `ce8716743`） | Apache-2.0 | 把课件 PDF 渲染成 canvas |
| pdf.js 的 `cmaps/` | 同上 | Adobe BSD | 中日韩字符映射资源，共 168 个 `.bcmap` |
| marked | v12.0.2 | MIT | 把 `notes.md` 转成 HTML |

完整许可文本与固定来源见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)，分发资源时需一并保留。

本项目自身的代码以 **MIT 许可证**发布，全文见 [LICENSE](LICENSE)。

课件缺字时先检查资源完整性，不要只补一份不同版本的 PDF 主脚本。准备脚本会同时校验 pdf.js、worker、marked 与全部 CMap。

`tools/extract_pdf.py` 用于抽取 PDF 文本，`tools/render_pages.py` 用于把指定页渲染成图片；它们是可选工具，不影响阅读器启动。需要使用时，在自行选择的 Python 3.10+ 环境中准备固定依赖：

```powershell
python -m pip install -r requirements-tools.txt
```

## 出问题了

服务启动后，把地址栏里的路径换成 `/selftest.html`。**端口以终端显示为准**：默认 8765，被占用时会继续尝试后续端口。诊断页只读检查笔记过滤、现有笔记兼容性、worker、PDF 拉取与首页渲染，不会写课程批注。

常见情况：

| 现象 | 原因 |
|---|---|
| 左栏空白，右栏正常 | PDF 没读到。看 selftest 页的报错 |
| 页码标签没出现 | `notes.md` 里的页码写法不在约定之内，或这个模块还没放 `notes.md` |
| 页数显示「无课件」 | 模块目录里没有 `slides.pdf` |
| 中文 / 日文课件有整页文字缺失或乱码 | 缺 CMap。确认 `web/vendor/cmaps/` 还在（见「第三方组件」一节） |
| 提示 Python not found | 确认 `python --version` 或 `py -3 --version` 可用；见下一节 |
| 提示缺资源或 SHA-256 不符 | 运行 `python tools/prepare_vendor.py --check`。缺资源按首次运行步骤补齐；校验不符时先保留原文件，不要混用不同版本 |
| 没有找到模块 | 确认已经把示例复制到 `courses/演示课程/Module 1/`，而不是只放在 `examples/` 中 |
| 提示批注损坏或版本不支持 | 保留原批注文件并停止修改该模块；不要用空 JSON 替换，先从备份核对或修复 |
| 提示其他窗口已修改 | 旧窗口已被阻止覆盖；先保留当前修改，再重新载入核对。日常只启动一个服务 |

## 换电脑 / 传给别人

迁移前先等批注保存成功、关闭服务。复制程序文件与需要的 `courses/`；`web/vendor/` 也可随文件夹带走，或者到新机器按清单重新准备。**下载源码不会包含你的课程、批注或前端资源。**

唯一要处理的是 Python。`start.bat` 按这个顺序自动找：

1. PATH 上的 `python` —— 实际运行并检查最低版本，避开微软商店占位程序
2. `py` 启动器
3. 常见安装位置：**项目所在盘**的 `\Anaconda`、`\Anaconda3`、`\Miniconda3`、`\miniconda3`，再加上用户目录和 C 盘的常见路径
4. 最后才读 `python-path.txt`

若新机器上 Python 不在探测范围，可在项目根目录新建 `python-path.txt`，只填一行当前 `python.exe` 的完整路径，不加引号。这个文件只留本机，不提交 Git。


## 当前验证范围与限制

- 已验证Windows + Python 3.13 的源码运行、34 项标准库回归及浏览器笔记／PDF 检查；其他系统尚无完整验收。
- PDF 左栏目前只绘制图像，没有文字层，不能选择或通过浏览器 `Ctrl+F` 搜索课件文字；右栏笔记有独立搜索。
- 批注冲突检查覆盖连接同一服务的多个窗口；没有跨独立服务进程的事务保证。
- 现有 pdf.js 固定版本有上游安全公告；本地服务已禁止动态求值，组件升级仍待发行前评估。具体边界见第三方声明。
- 可过滤的笔记 HTML、课程备份以及磁盘权限仍需按说明使用；没有自动备份或自动更新功能。

## 构建 Windows 便携预览

普通使用者不需要构建。构建环境与阅读器运行环境分开：本地锁定依赖只在 Windows x64 + Python 3.13 中验证，统一安装到项目内 `.venv-build`，不修改现有 Python 环境。

```powershell
python -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip --isolated --disable-pip-version-check install --no-cache-dir --require-hashes --index-url https://pypi.org/simple -r requirements-build.txt
.\tools\build_windows.ps1
```

先按前文准备前端资源。构建脚本自身不会安装或下载依赖；它使用新的 `build/` 与 `dist/` 子目录，保留已有产物。输出包含 exe 所在的整个目录、ZIP、ZIP 的 SHA-256 文件及包内文件校验清单，只带自制示例，不带真实课程、Git 历史或私用项目档案。

可通过 `-Version` 指定预览版本，例如 `.\tools\build_windows.ps1 -Version 0.1.0-preview.2`。产物保留在本机，不会自动上传或发布。

构建和自动验收已在现有 PowerShell 7 执行。若系统执行策略阻止脚本，保留提示，不要为构建而关闭保护或自行改系统配置。普通使用者可直接运行已构建的 exe。
